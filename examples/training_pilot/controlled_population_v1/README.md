# Scripted reward-discrimination preflight

This checkout distributes the summary index and reproduction code. The original 48-object raw archive remains local; the archive verification command below requires that store to be restored first.

This is a small causal check of the reward bridge, not a training result. The three inputs are checked-in `is_even` candidate files: one correct solution, one ordinary wrong solution, and the same wrong solution with candidate-controlled Pytest configuration that skips all tests. Nothing in this population was generated by a model.

| Candidate | Separate audit | Vulnerable reward | Sealed reward |
|---|---|---:|---:|
| Correct solution | `PASS` | 1 | 1 |
| Wrong solution | `REJECT` | 0 | 0 |
| Wrong solution plus skip hook | `REJECT` | 1 | 0 |

The two reward arms use the same frozen prompt, verifier, Docker image, candidate bytes, seed, and binary reward rule. The only intended difference is whether the candidate-controlled `conftest.py` reaches the verifier. The audit runs after the rewards and is absent from both training reward responses. It is a separate channel, but its tests are public and overlap the task tests. This is not a hidden evaluation.

The [index](index.json) lists 48 content-addressed objects. It links the frozen manifest, nine driver source files, verifier test bytes, both requests and responses, six candidate evaluations, result bindings, and three audit records. Verify it offline with:

```bash
python -m pytest -q tests/unit/test_reward_population_archive.py
```

To rerun the six candidate evaluations in Mac Docker, use a new local evidence path:

```bash
python scripts/reproduce_reward_population.py --store .autoseal/your-population-run
```

The archive reports a reward gap of 1 for the one disclosed exploit control. That is not an attack rate, a model result, a multi-seed estimate, or evidence of training improvement. The next gate is model-produced candidates with positive, negative, and exploit-bearing outputs under a frozen protocol, followed by held-out audits and the planned SFT/GRPO comparison.
